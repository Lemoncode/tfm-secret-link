# Agents — entry protocol

> Lemony harness · vendor `0.12.0` · target `claude-code`.
> Generated by `lemony install` at `.claude/agents/entry-protocol.md`; safe to edit.

This is the **dispatcher** the Orchestrator follows on every session. The
Orchestrator is the single human-facing hat; it invokes sub-agents (Planner,
Implementer, Reviewer, and the on-demand Architect / UI Designer / Spike Runner) with
fresh context via the Task tool. Role rules: `.claude/agents/<role>.md`.

## Mode dispatcher

Parse the intent of the first prompt (or honor an explicit slash command):

| Intent signal | Mode |
| --- | --- |
| "continue", "resume", "pick up" + a `#id` or name | **RESUME** |
| "new task", "I have an idea", "I want to build" (no command) | **NEW WORK** |
| `/define` | **DEFINE** |
| "bug", "error in", "it's broken", "fails when", "crash", `/triage` | **TRIAGE** |
| a change to make (rename, fix, add, edit), not the Architect's work below | **NEW WORK** |
| a bare greeting / orientation question / nothing | **ORIENT** |

If the intent is ambiguous **between harness modes**, ask **one** disambiguation
question, then proceed. A concrete **non-harness** request (it edits no file) is just
answered — don't surface the menu.

- **NEW WORK** — the task-flow round-trip (see below).
- **DEFINE** — `/define`: the task flow, grill first.
- **RESUME** — first, an issue carrying `harness:sdd` is a 0.11.x spec task, which this
  version no longer runs: touch nothing, whatever its status (no checkout, step, label or closeout); say it is
  finished on the version it started with (0.11.x), or closed as not planned and redone
  with `/define`, and stop. Then, an `in-progress`, `in-review` or `paused-for-clarification` task
  is routed by its task PR (found with
  `gh pr list --state all --search "head:harness/<id>-"`), before any checkout: merged →
  no task branch to check out, run [`task-closeout`](.claude/skills/task-closeout/SKILL.md) (retry-safe; a paused one resolves its
  discovery first); closed unmerged → offer resume / abandon / leave it; no PR on an
  `in-review` task → ask the human for its number. Then, for a task that has left
  `pending`, `git fetch` and check out `harness/<id>-<slug>` before reading any state
  (the task state lives only on the branch until merge), then reload `.claude/state/tasks/<id>/` and
  continue from `progress.md`. An issue carrying
  `harness:partition-plan` is a partition parent, not a task — resume it per
  `.claude/agents/partition.md` (its feature PRD first, then its next part).
  Before acting on the task, read `.claude/agents/orchestrator.md` §"Dispatch" → RESUME
  (the routing per status — a pending stub, closeout-pending, a parked design, a pause —
  is not summarized here); a `plan-ready` pickup resumes at `.claude/agents/task-flow.md` step 6, its gate before code.
- **TRIAGE** — the task flow from its step 1, triage (see below).
- **ORIENT** — an intentless entry (greeting, "what should I pick up?", nothing).
  Render the **dispatch menu**: the parked queue (what `/resume` lists with no
  args, **pending issues** included) plus the start options (describe
  new work, `/define`, `/triage`), and ask which to do. The start options are **unconditional** — an empty
  queue still renders the menu with just them. If `gh` is absent or unauthenticated, skip
  the listing and still offer the start options — never block.
  Authority + the full guard: `.claude/agents/orchestrator.md` §"Dispatch" → ORIENT.

A request for the **Architect**'s work — record an ADR, capture how the project does
something, change a convention, import documentation — is dispatched to the Architect
(Task tool, fresh context) as `.claude/agents/orchestrator.md` §"Architect (on-demand)"
says; never run its skills in this session.

## Paths

- **Task flow** — every request and every part of a cut feature: a grill first
  when the router finds open decisions, or on `/define` (a part's grill at its turn).
- **Bypass** — `/bypass`, typed by the human only: no issue, no review.

A task deserves the harness if it is **specifiable**, **verifiable**, or
**reviewable** (≥1). If none (a typo, an internal rename), ask once — `/bypass` or
the harness (any other reply), recommending neither — before opening anything; never run it or its steps yourself. Never offer it for an
incompatible change to what others consume (a CLI flag or command, output scripts read, a config
key, an export, a file format). The router: `.claude/agents/fit-assessment.md`.

## Task-flow round-trip (NEW WORK, DEFINE, TRIAGE)

Read `.claude/agents/task-flow.md` (again after a compaction) with your Read tool, not a
`cat`: it is past the shell's ~30 KB output cap, so a `cat` costs a second read. Run it
from the step you enter at: the full rules for each step's labels and commands are there.

A skill you run in this session (triage, the grill, the closeout, a discovery's
resolution) is read first with your Read tool (again after a compaction): its
`.claude/skills/<name>/SKILL.md` whole, unless the step that sends you there says to
read only some parts of it, as a part's grill does. What you do can lean on any part
of it, and a shell read can give you less: a `cut` or a line range keeps what it
selects, a composite command that exits non-zero comes back cut to ~10,000 characters
with its middle gone, and an output past ~30 KB as a 2 KB preview.
The `Skill` tool can load a personal skill of the same name instead.

- **Steps 1–3, triage and route** (a bug: triage) — [`triage-issue`](.claude/skills/triage-issue/SKILL.md); then the router; a grill ([`grill-with-docs`](.claude/skills/grill-with-docs/SKILL.md)) when open — separable wants → the partition question (`.claude/agents/partition.md`).
- **Step 4, open the task** — issue + branch `harness/<id>-<slug>`; nothing touches the default branch until the merge gate.
- **Step 5, plan** — UI design only if the task touches UI; Planner, `tasks.md`.
- **Step 6, gate before code** — the agent's calls, then the mode and auto-commit (orchestrator §"Implementation mode"); never answer it yourself.
- **Step 6, then implement** — Implementer, [`tdd`](.claude/skills/tdd/SKILL.md); a step-by-step resume re-enters at its step log (orchestrator §"Step-by-step implementation").
- **Step 7, review** — open the PR (`Closes #<id>`), then flip to `harness:status:in-review`; Reviewer, full pass — it owes its own review passes, so the prompt names none (+ the UI Designer if it touched UI). The APPROVE's evidence ledger is validated by a script (`lemony review-ledger validate`), never by an agent.
- **Step 8, merge gate** — never auto-merge; an authorized merge runs through `.claude/hooks/lib/merge-pr.sh <pr> --approve-issue <id> --squash`, which checks the APPROVE still matches the content (orchestrator §"Merge gate").
- **Step 9, closeout** — [`task-closeout`](.claude/skills/task-closeout/SKILL.md) (orchestrator §"Closeout").

## Discovery interrupts

At any step, a sub-agent that hits a T1–T6 case (contradiction, unspecified decision,
scope drift, existing solution, infeasibility, convention conflict) **pauses instead of
guessing**: it runs [`raise-discovery`](.claude/skills/raise-discovery/SKILL.md), writing `tasks/<id>/discoveries.md` and
returning a one-line summary. The Orchestrator then runs [`resolve-discovery`](.claude/skills/resolve-discovery/SKILL.md) — the
task moves to `harness:status:paused-for-clarification` (+ `harness:discovery:T*`), the
human arbitrates, the owning agent updates its artifact, and the paused sub-agent
resumes. No discovery may remain unresolved at closeout.
